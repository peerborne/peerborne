## The runtime, at a glance

![UI and React hook connected to an in-memory CRDT; signed and encrypted updates flow to the Helia blockstore and libp2p, with epoch keys supplied to the crypto layer.](/diagrams/runtime.svg)

Encryption comes before storage and transport. Change transactions combine

## Choose the stack for your constraints

Peerborne composes these CRDT engines. Choose it when you want to experiment
with their merge semantics inside an encrypted peer-to-peer stack.

| | Peerborne | Yjs + providers | Automerge + Repo | WebSockets + Postgres |
| --- | --- | --- | --- | --- |
| **Transport** | libp2p; WebRTC / configured relays | Choose a network provider | Choose Repo adapters | App server broadcasts |
| **Document E2EE** | Built in; group lifecycle is alpha | Provider/application choice | Separate from baseline Repo | Add application encryption |
| **Storage** | Encrypted Helia blocks / IndexedDB | Add persistence provider | Repo storage adapter | Server database + app cache |
| **Client memory** | Loaded CRDT + graph/caches; no total cap | Loaded CRDT + metadata | Loaded docs + history | Choose a client working set |

Yjs providers can add encryption, including a shared password in y-webrtc.
This compares the baseline architectures; it does not rank speed, maturity, or
safe document sizes. See [sources and trade-offs](/reference/comparisons/).

## Measure the work your app actually does

Inspect the [benchmark sources](https://github.com/Peerborne/peerborne/tree/main/packages/core/src/__benchmarks__)
and [measurement guide](/concepts/performance/): crypto operations, simulated
update delivery, and index queries are different workloads. The committed benchmark snapshot records its
machine, runtime, source commit, and sample counts. A pinned ESM runner makes
the workloads reproducible; the guide includes bounded smoke commands. Results
remain informational, with no CI performance thresholds or browser frame-budget
guarantee.

The default browser smoke test opens one real encrypted document. A separate
cross-NAT acceptance suite verifies a signed distinct-identity invitation and
live bidirectional updates through Circuit Relay. Partition/rejoin convergence,
restart recovery, and relay failover still
need stronger evidence. [Review current limits →](/concepts/limitations/)
